# ZTAB

ZTAB is a broker running inside a Trusted Execution Environment
(TEE) that allows autonomous agents representing different,
mutually distrustful entities to securely coordinate, exchange
sensitive data, and negotiate shared outcomes.

By utilizing TEEs and encapsulated LLMs, ZTAB enables agents to
submit private inputs to a shared session and receive verified
common outcomes, without exposing their raw inputs to other
participants or to the cloud infrastructure provider.

## Core Features

*   **RA-TLS (Remote Attestation TLS):** Connections are
    established over TLS 1.3, where the server's ephemeral
    public key is cryptographically bound to a **Remote
    Attestation Report (OIDC JWT)** generated by Confidential
    Computing-enabled hardware (e.g., Intel TDX), and
    potentially vetted by a third-party verifier (e.g., Intel
    Trust Authority, if running on Intel hardware). Clients can
    verify the claims and endorsements in the attestation report
    to confirm the integrity of the TEE's hardware and software
    state, before transmitting data.

*   **Encrypted Memory:** All session states, agent inputs, and
    LLM activations remain in encrypted memory, protected from
    the host hypervisor and cloud provider.

*   **Multi-Party Sessions:** A gRPC-based session state machine
    coordinates multiple agents submitting private inputs to the
    same LLM session, and combines their outputs into a single
    shared outcome using a previously agreed-upon prompt and/or
    other instructions.

The framework supports the full multi-party session lifecycle:
session creation with admission control, policy agreement,
private input submission, LLM inference inside the TEE, and
result retrieval. End-to-end agent coordination has been
validated using the cold-start test harness with real agents
coordinating calendar scheduling sessions.

## Quick Start

> **Note:** Additional platform-specific deployment steps may
> be needed for production environments. Further guidance will
> be incrementally added.

### 1. Run the TEE Server (Docker)

```bash
cd tee
./run_server.sh --port 8000                  # build and start on port 8000
./run_server.sh --port 8000 -d               # detached mode
./run_server.sh --llm --gcs_bucket gs://your-bucket     # Run with LLM model weights
```

To enable admission control (token-gated session creation):

```bash
./run_server.sh --llm --gcs_bucket gs://your-bucket \
    --creator_token SECRET
```

### 2. Run the TEE Server (GCP Confidential Space)

For end-to-end hardware testing on GCP with H100 GPUs and Intel TDX, see the internal testing guides for building and pushing the Docker image to Artifact Registry. Once pushed, you can launch the node using the provided scripts:

```bash
# 1. First-time setup (creates Instance Template and Managed Instance Group)
./scripts/launch_gcp.sh --mode=setup --ita_api_key=YOUR_ITA_KEY

# 2. Request a node (uses Dynamic Workload Scheduler for GPU queuing)
./scripts/launch_gcp.sh --mode=launch

# 3. Poll until the VM is allocated and get the IP
./scripts/launch_gcp.sh --mode=get-ip
```

### 3. Set up the Python Agent Client

```bash
cd agent
pip install -r requirements.txt   # grpcio, grpcio-tools, etc.
python3 generate_protos.py        # compile proto stubs
```

For automated MCP server registration and backend configuration:

```bash
agent/install_mcp.sh \
    --backend-id local --host localhost --port 8000
```

### 4. Verify Connectivity

```bash
# Raw TLS + attestation extraction (no grpcio needed):
python3 diagnose_tls.py --host localhost --port 8000

# Full gRPC Echo RPC over RA-TLS:
python3 cli.py --host localhost --port 8000 \
    --message "Hello ZTAB"

# Automated MCP protocol smoke test:
python3 smoke_test.py --host localhost --port 8000
```
